# BranchLens — Institutional DeFi Risk Intelligence

**See beyond the position.** BranchLens is an independent, read-only DeFi risk prototype built for the Belem Capital DeFi Risk Challenge. Six starter **illustrative investments** in **real Ethereum Morpho V1 vaults** support dependency and reverse impact investigations. Analysts can add their own hypothetical vault or direct market holdings on Ethereum and Base. The supplied logo is at `public/branchlens-logo.png`. The product is neither a wallet nor an execution system.

## Public demo

The GitHub Pages URL serves the static graph/replay. The borrower risk, stay/exit, approval, simulated bot and report workflow requires the local Node API or a Vercel deployment. Vercel **does not require `DATABASE_URL` for the hackathon browser demo**; simulated runs are kept in that browser. The workflow is not functional on GitHub Pages.

[Open the hosted judge demo](https://kyokoussin.github.io/Branchlens-Belem-Hackathon/). The six starter positions use the **saved historical Morpho API snapshot** captured on 10 October 2026 at 23:49 UTC until the analyst chooses to refresh live data or manages positions. New vault and market IDs are verified through Morpho's public API; user-configured holdings and portfolios stay in browser localStorage, separate from cached Morpho responses. The app does not monitor current incidents. Every position shows whether its data is live or historical. The hosted bundle is in `docs/`. After changing code or the verified snapshot, run `pnpm pages:build`, commit, and push `docs/` with the source changes to update the site.

## Launch on this Mac

Double-click **Start BranchLens.command** and leave its Terminal window open, then visit [http://127.0.0.1:8780](http://127.0.0.1:8780). The app fetches live public Morpho data when available; if it cannot, it labels and uses the bundled historical API snapshot. The **Use historical snapshot** control is beside the investment cards for offline rehearsal. Closing Terminal stops the local app.

For a manual start with Node and pnpm:

```sh
pnpm install --frozen-lockfile
pnpm build
pnpm start
```

## Judge walkthrough: complete local/API demo

1. Start the app with **Start BranchLens.command** or `pnpm start`, then open http://127.0.0.1:8780. Confirm the portfolio is labeled illustrative and inspect **Portfolio Graph** or a position's Dependency View. Shared market, token and oracle IDs come from Morpho, with source evidence on the graph.
2. Choose **Run Simulated Incident**. The workflow selects a real Ethereum Morpho Blue cbBTC/USDC market. Set **Data source** to historical snapshot for a deterministic rehearsal, or leave **Live API, verified fallback** for a fresh retrieval. The UI displays the actual source mode and capture time.
3. Run the default hypothetical position of 1 cbBTC collateral and 60,000 USDC debt with a 30% collateral shock. Check reverse paths to all connected tracked positions. The exposed principal is unique illustrative capital; it is **not** a loss estimate for the supplier positions.
4. Inspect the borrower's before/after collateral value, debt, equity, LTV and health factor. HF at or below 1 means liquidation eligibility, not an observed liquidation.
5. Acknowledge and investigate the simulated incident. In **HOLD VERSUS EXIT**, change **Requested exit share** to 40%, recalculate, and inspect the remaining collateral exposure and proportional repayment requirement. The probability and costs are analyst assumptions; the execution quote is **NOT QUOTED**.
6. Record **PARTIAL EXIT** with a justification, send the versioned instruction to the **simulated bot**, and open/download the persisted audit report. The intent records requested token amounts and residual exposure. The acknowledgement is **simulation only**; no trade is executed or incident resolved.

For a three-minute walkthrough: portfolio and real graph (0:00–0:30), run the cbBTC scenario and verify source/affected paths (0:30–1:15), inspect borrower health and unique exposure (1:15–1:45), set 40% partial exit and recalculate (1:45–2:15), approve, send the simulated handoff, and open the report (2:15–3:00).

For a longer walkthrough, open **Portfolio Graph** from navigation to inspect the merged graph across all portfolios. Select a shared market or collateral node to see its complete paths and unique exposed principal. The dashboard and explorer share search and combined portfolio, protocol, asset, market, oracle, and risk filters. Edit, move, or remove a simulated position to see the graph and impact update immediately. Browser refresh restores configured holdings.

**Add Position without a wallet:** Open **Manage Positions**, choose Ethereum or Base, then search the live public Morpho market list. Combine collateral and loan asset filters or load more listed markets. Select a market to see its real ID, token addresses, oracle, LLTV and current market totals; BranchLens verifies its full dependency data before saving. Choose **Supply** and enter hypothetical supplied USD, or choose **Borrow** and enter hypothetical collateral and debt USD. The borrow form checks the debt against the selected market's LLTV. Save to add the simulated holding to the portfolio and shared dependency graph. No Morpho account, wallet, signing or cryptocurrency is required. The list contains loaded pages of listed markets; loading more expands the searchable set. Existing saved positions remain editable, and old positions without a type are treated as supply.

## Technical MVP and deployment

The local API persists portfolio configuration, market snapshots, scenario runs, approvals, simulated bot handoffs and reports in `./.branchlens.sqlite` (ignored by Git). The database schema is in `migrations/001_mvp.sql`. Set `BRANCHLENS_DB_PATH` to move the local database. On Vercel without `DATABASE_URL`, BranchLens uses a database-free browser demo: the current simulated run is saved in that browser's localStorage and sent with each workflow request, including report generation. This survives refresh in the same browser but is **not shared across browsers or durable server storage**. For shared durable records, configure a server-side PostgreSQL `DATABASE_URL`; never prefix it with `VITE_` or commit it. `vercel.json` builds `dist` and packages the Node API. GitHub Pages remains a static graph/replay.

The portfolio revalidates public Morpho observations every 60 seconds while the page is open in live mode; active borrower-market requests share a 60-second cache. Structure, market measurements, total assets, and rule observations are compared separately. There is no background worker or 24/7 monitoring. Token prices older than 12 hours reject live calculations; a matching timestamped Morpho snapshot is used only as a visibly labeled historical fallback. Re-capture a verified borrower snapshot deliberately with `pnpm capture:borrower` while the public Morpho API is reachable. The included snapshot matches market `0x64d65c9a2d91c36d56fbc42d69e979335320169b3df63bf92789e2c8883fcc64` on Ethereum.

The borrower model uses verified market LLTV and Morpho token USD prices with analyst-entered balances. Collateral value = collateral tokens × collateral USD price; debt value = debt tokens × loan USD price; LTV = debt / collateral; health factor = collateral × LLTV / debt. A price shock recomputes these values using decimal-safe arithmetic. Conditional lender shortfall = max(0, debt − shocked collateral value), an upper-bound scenario quantity rather than realized loss. Supplier positions only receive graph exposure; borrower health is never applied to them. Unsupported oracle-stale, oracle-deviation and protocol-unavailable economics return an explicit unsupported result.

The HOLD/EXIT calculation uses analyst-entered probability × incremental loss × requested exit share, compared with analyst-estimated gas, swap slippage, fees and unwind costs. At a 40% partial exit, the model assumes proportional debt repayment and collateral release, and reports the remaining 60% collateral and debt exposure. This is a scenario assumption, not an executable quote. Loan repayment is a funding requirement, not a transaction cost. Zero slippage in the demo assumes the analyst already has the USDC loan asset; otherwise a swap quote and cost are required. The app does not fetch executable quotes, estimate exploit probabilities, know the user's actual wallet balances, or guarantee that an exit fully removes risk. Its intent states `quoteStatus: NOT_QUOTED` and has no maximum executable-cost constraint. The handoff schema is validated and idempotent; its receiver never signs or submits an on-chain transaction. This is a shared demonstration workspace, not a private authenticated service.

## Data and financial meaning

See [CALCULATIONS.md](CALCULATIONS.md) for the exact dependency-share, unique exposure, borrower-risk, and stay-or-exit formulas, including a worked saved-snapshot example.

- **Live by default:** `api/_morphoClient.mjs` requests current Morpho GraphQL vault and market records and the V1 vault-state REST record. All six addresses in `api/_portfolioConfig.mjs` were checked against the API. The app uses vault allocations, market IDs, loan/collateral assets, oracle addresses and available upstream feed/vault addresses, market liquidity, utilization, LLTV, indexed block when supplied, and retrieval time. The query and normalization are shared across all three screens.
- **Verified fallback:** `data/demo-snapshot.json` is a timestamped saved response from the same public API, captured by `scripts/captureSnapshot.mjs`. Each position is labeled **LIVE MORPHO DATA** or **SAVED HISTORICAL SNAPSHOT**. A mixed mode is possible if only some live requests fail. The saved file must never be described as current market state. Re-capture deliberately with `node scripts/captureSnapshot.mjs` when a fresh verified backup is needed.
- **Assumed capital:** $1,000,000 Steakhouse USDC, $500,000 Gauntlet USDC Core, $250,000 Gauntlet WETH Prime, $400,000 Gauntlet USDC Prime, $300,000 Smokehouse USDC, and $200,000 Yearn USDC. These are scenario inputs, not real portfolio holdings. Market-attributed principal = assumed position amount × reported market allocation USD ÷ reported vault total assets USD. `api/_riskEngine.mjs` rejects materially inconsistent totals; uncovered capital is retained as unattributed. Shared dependencies resolve to the union of underlying funded markets, so the same market allocation is counted once per position.
- **Bidirectional graph:** Dependency View follows outgoing relationships from one investment. Impact View uses the same nodes and edges in reverse, finds every path to tracked positions without a depth limit, and lists all intermediate components. Each edge records direction, type, source field, retrieval time where available, and `API`, `VERIFIED_REFERENCE`, or `UNKNOWN` provenance. The portfolio result distinguishes distinct market IDs from funded allocations across positions. Exposure is summed once per position after its affected market IDs are deduplicated; a vault-wide dependency reaches the full assumed principal, including unattributed capital.
- **Dependency evidence:** Vault, market, collateral, loan asset, oracle and available oracle upstream links come from Morpho records and are tagged **OBSERVED**. Coinbase issuer, custody and BTC backing links for the documented cbBTC Ethereum contract are tagged **DOCUMENTED**, reflecting Coinbase's published claims rather than an independent reserve verification. Missing oracle internals and other unsupported links stay unknown. The graph reuses shared node IDs.
- **Risk signals:** Structural concentration checks for shared collateral/oracles are observations, not emergencies. Findings record rule/dependency ID, observed value, threshold, timestamp, provenance, affected position, and unique exposure. The cbBTC price rule can evaluate a supplied verified baseline/observation pair, but this demo has no trusted live pair; its live status is **UNKNOWN**. The replay supplies an explicitly **SIMULATED** pair and triggers one deduplicated portfolio incident. Analyst status can advance through acknowledgement, investigation, decision and pending execution; **RESOLVED** requires external verification and is never asserted by a simulated handoff.
- **Calculated demo stress, not observed loss:** The incident identifies funded cbBTC markets and reports unique simulated principal. The default Impact View applies the explicit 30% collateral-stress formula in [CALCULATIONS.md](CALCULATIONS.md), using Morpho borrow, supply, LLTV and liquidity with stated assumptions about vulnerable borrowers and recovery. The immediate exit gap is a market-only liquidity proxy, not a wallet withdrawal quote. A chain outage instead models 24-hour inaccessibility and opportunity cost. Realized bad debt, vault share-price effects and actual execution costs remain unverified. The advanced market bad-debt scenario still distinguishes V1.0 from V1.1 accounting; no transaction can execute.
- **Scope:** The starter vaults are Ethereum Morpho **V1**. Managed positions can reference V1 vault addresses or Morpho market IDs on Ethereum or Base. A direct market holding uses reported market supply for its 100% market allocation and links the assumed position directly to that verified market; no intermediary vault is invented. V2 adapter semantics are different and are not modeled. This prototype has no connected portfolio wallet, persistent monitoring service, real live depeg feed, signing, external alert delivery, or trading execution.

Sources: [Morpho API documentation](https://docs.morpho.org/developers/api/morpho-vaults/), [Morpho market API documentation](https://docs.morpho.org/developers/api/morpho/), [Morpho GraphQL endpoint](https://api.morpho.org/graphql), and [Coinbase cbBTC documentation](https://www.coinbase.com/cbbtc).

## Verify

```sh
pnpm test
pnpm build
pnpm smoke:live
```

The tests cover graph/exposure behavior, borrower health and token precision, HOLD/EXIT economics, missing assumptions, persisted approval/report, intent validation, simulated receiver expiry and duplicate handoff. `smoke:live` needs internet access. The local server serves `/api/portfolio` (`source=auto` or `source=snapshot`, optional `scenario=CBBTC_DEPEG_30`), `/api/analyze` for a single Ethereum V1 vault, and `/api/health`. Managed holdings are analyzed in the browser using the same portfolio engine and Morpho GraphQL data model.
